# 让量化策略自己写规则：从「选最优」到「不断进化」的闭环交易系统

> 元数据：作者：数据科学实战（微信公众号） | 日期：2026/07/18 00:00 | 来源：微信文章 | 链接：https://mp.weixin.qq.com/s/X7bQfzKoYPvgJWElvmt1yQ

## 一、关键信息提取

### 核心观点
- 传统量化回测解决的是"横向选优"（候选池里挑相对最优），框架本身不积累经验；本文主张"纵向进化"——系统在运行中持续记录、复盘、修正每笔交易，把经验沉淀为可复用的规则。
- "进化"不是机器学习在线训练/更新大模型权重，而是**外部经验库（Playbook）持续更新**：把交易复盘写入数据库，汇总成操作手册，让下一轮决策读取它。业界称"上下文工程/基于外部记忆的智能体"。
- 用单品种（BTC/黄金/原油永续合约）做闭环实验，因为单一市场特征可反复沉淀；但明确警示：单品种样本积累慢、早期易把噪声当规律，初期应作为"观察和迭代对象"而非成熟实盘系统。
- 核心设计原则：闭环可以调整"怎样做得更好"，但不能放松"允许承担多少风险"的底线——AI 只能建议，代码层用 clamp 兜底。

### 关键数据与事实
- 五阶段闭环：感知 → 决策 → 执行 → 复盘 → 更新。
- 感知层指标清单：EMA（快/慢线）、MACD 柱（含是否放大布尔位）、RSI(14)、KDJ（K/D）、布林带上下轨、ATR 占价格百分比、成交量相对 20 日均量比值。
- 决策层硬规则：技术观点与新闻观点冲突时不允许开仓或加仓，动作必须为 hold 或 close；confidence 必须诚实反映确定性（0-100）。
- 执行层仓位公式：`size_pct = base_pos_pct × clamp(confidence/100, 0.4, 1.0)`——置信度越低实际仓位越小。
- 执行层置信度门槛：`action in (open_long, open_short)` 且置信度低于阈值则放弃开仓。
- 复盘层错误类型分类：none / chased_move（追涨杀跌）/ ignored_news_conflict（忽视新闻冲突）/ stop_too_tight / stop_too_wide / overleveraged / held_too_long。
- 复盘触发条件：仅当一笔完整交易（开仓到平仓）结束后才生成教训；教训必须是具体结论（示例："RSI 超过 70 后、且新闻环境偏空时追多，容易被套。等回调或直接放弃"），禁止"操作失误/行情不好"类空话。
- 更新层：复盘积累到一定数量或固定时间窗口后触发 Playbook 更新；每个可调参数（min_confidence / base_pos_pct / hard_stop_pct / trail_activate_pct / trail_giveback_pct）都被 clamp 到人工设定的 [下限, 上限]，精确到 4 位小数。
- 硬约束四层：① AI 不能改代码，只能区间内微调参数；② 硬止损、单品种最大仓位、最大加仓次数代码层强制（硬参数不可被 AI 放松，与软参数分离）；③ 新开仓要求技术/新闻至少不冲突；④ 默认支持"仅通知"模式，先观察再实盘。
- 最大仓位检查：`max_qty = equity × MAX_SINGLE_POS_PCT × LEVERAGE / Last / margin`，超限则削减；`add_count >= MAX_TOTAL_ADD_COUNT` 时拒绝加仓。
- 成熟持续学习系统 vs 本闭环的差距表：更新对象（权重 vs 外部 Playbook）、样本量、新版本验证（影子/A-B/样本外 vs 直接生效）、归因可靠性（统计方法 vs 大模型定性归因，有事后偏见）、环境变化检测（概念漂移 vs 固定笔数/时间触发）、参数变更依据（显著性检验 vs 近期复盘+模型总结）。

### 方法论 / 操作要点
- 单品种可自我进化 AI 交易闭环的工程实现要点（含 Python 代码思路）：
  1. 感知层：把散乱指标组装成**带语义的结构化快照**（按 trend/momentum/volatility/volume 分组，含布尔字段如 `macd_hist_rising`），而非原始数值直接塞给模型——"结构化优于原始数据"。
  2. 决策层：快照 + 近期新闻 + 持仓状态 + 当前 Playbook 一起喂给大模型，输出结构化信号（动作/方向/置信度/技术观点/新闻观点/理由）；技术面与新闻面"不冲突"是开仓必要条件而非充分条件。
  3. 执行层：参数从 Playbook 读取但必须 `clamp(v, lo, hi)` 到人工边界；仓位按基础仓位×置信度缩放。
  4. 复盘层：完整交易结束后才复盘，输出具体教训 + 错误类型分类入库。
  5. 更新层：定期汇总近期复盘与胜率盈亏统计，生成新 Playbook（该做/该避免规则 + 参数调整建议），参数逐一裁剪后写回。
- 部署建议：先用"仅通知"模式观察信号/复盘/Playbook 演化质量，再进入小仓位实盘。

### 文章结论
- 搭好"决策→执行→复盘→更新"闭环只是第一步，它把记录、复盘、总结、更新、复用经验这些原本靠人工的活动结构化；能否积累真正有用的经验，最终靠足够时间、足够样本与严格风控检验，对进化结果应保持敬畏。

### 对 A 股投资系统的借鉴点
- 五阶段闭环可映射到"白泽"全链路：感知（DataWorker + 指标快照）→ 决策（analysis-worker 多维分析）→ 执行（positioning + risk-control）→ 复盘（learner 反馈）→ 更新（calibrate/进化）。可把"决策→执行→复盘→更新"作为系统 `learner` 模块的架构蓝本。
- **结构化快照思想**：与白泽"DTO 优先"原则同向——把散乱指标组装成语义化、带布尔字段的结构化输入，提高下游分析稳定性。可借鉴 `macd_hist_rising` 这类布尔字段设计，落入学 factor/diagnosis 的特征工程。
- **软硬参数分离 + clamp 兜底**：直接可落地——AI/LLM 生成的分析建议只能调整软参数（如仓位百分比、止损百分比），而硬边界（最大仓位、最大加仓次数、硬止损、单票敞口上限）由代码层强制，防止模型"自我放松风控"。这与白泽"仅 SignalWriter 可写 + L4 风控硬约束"完全同构。
- **置信度映射仓位**：`仓位 = 基础仓位 × clamp(confidence, 0.4, 1.0)` 与白泽"confidence < 0.6 不进 L3"的分制思想互补，可引入"置信度连续化仓位缩放"到 positioning 模块。
- **双信号源"不冲突"才开仓**：对应白泽"交叉验证 ≥2 独立来源"护栏——把"信息面冲突即禁止开仓"作为硬规则，防止单一信号源触发交易。
- **复盘错误类型分类**（chased_move / ignored_news_conflict / stop_too_tight 等）：可直接作为 `learner` 的反馈标签体系，让复盘从"空话"升级为可统计的错误类型库。
